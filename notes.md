## Решение, которое нужно от тебя: robots.txt

Задание требует только 1 запрос/с и честный User-Agent. Я пошёл дальше: сборщик соблюдает robots.txt
у всех сайтов. Но у пяти УК robots.txt закрывает от роботов единственный источник СЧА и пая: ПСБ (16 фондов),

`ROBOTS_EXCEPTIONS` в `pif/config.py`, у каждого записана причина. Аргумент «за»: это обязательное раскрытие
по закону, а не закрытый раздел. Если хочешь строго — удаляем строки, и у 40 фондов будет статус
«закрыто robots.txt». Мой совет — оставить и спокойно объяснить на созвоне.

## Как часто обновляются данные

- **Автоматически раз в день, в 21:00 МСК** — workflow «Update data» в GitHub Actions: докачивает новые точки,
  проверяет качество и, если ошибок сбора/разбора нет, коммитит данные; Vercel сам пересобирает сайт.
  Если проверка не прошла — ничего не публикуется, на сайте остаются вчерашние данные, в Actions видно почему.
- УК публикуют СЧА и стоимость пая за день обычно на следующий рабочий день, поэтому на сайте — данные
  на прошлый рабочий день. Интервальные фонды и часть мелких УК публикуют реже (раз в месяц) — так и показано.
- Реестр ЦБ (список фондов) перечитывается при каждом прогоне: новые фонды появятся сами, закрытые уйдут.
- Запустить обновление вручную: GitHub → Actions → Update data → Run workflow.
- Можно чаще (например, утром и вечером), но смысла мало: УК обновляют данные раз в день.

## РСХБ — собирается только из GitHub Actions (важно!)

- Итог 04.11: 14 из 14 фондов РСХБ с полным рядом, вся официальная доходность сошлась с нашим расчётом.

- Сайт РСХБ Управление Активами (14 фондов) **не открывается с сервера, где идёт разработка**, но открывается
  с серверов GitHub. Поэтому адаптер `pif/sources/rshb.py` разведан и проверен через GitHub Actions:
  workflow «Recon» (`.github/workflows/recon.yml` + `scripts/recon.py`) скачивает нужные адреса тем же вежливым
  клиентом и отдаёт ответы артефактом.
- Данные РСХБ в демо появляются из ежедневного обновления в Actions. Локальный `python -m pif all` с машины, откуда
  сайт не открывается, пометит фонды РСХБ «не обновилось» и покажет прошлые данные — это ожидаемо.
- robots.txt РСХБ (шаблон Битрикса) закрывает адреса с параметрами, а график СЧА и пая грузится именно так —
  РСХБ добавлен в исключения с причиной, как ПСБ.
- На созвоне можно рассказать как пример: «сайт недоступен из моей сети — разведал и собираю через CI».

## Как всё устроено (то, что спросят на созвоне)

- `python -m pif all` — одна команда: реестр → сбор → нормализация → притоки → сверка → отчёт качества.
  `make all` — то же плюс сборка сайта.
- **Реестр** (`pif/registry.py`): xlsx Банка России «Сведения о ПИФ» → фильтр «открытый/интервальный/биржевой»,
  статус «сформирован/формируется», не для квалов → 395 фондов у 52 УК. ИНН УК — из реестра лицензий УК ЦБ
  (склейка по ОГРН, в реестре фондов ИНН нет). ISIN/тикер — ISS Мосбиржи (склейка по номеру правил).
- **HTTP-клиент** (`pif/http.py`): 1 запрос/с на домен, честный User-Agent, каждый ответ сохраняется в `raw/`
  (в git не лежит), в `data/manifest.json` — адрес, дата, формат, SHA-256, какие фонды. Повторный запуск
  в течение 20 часов в сеть не ходит; позже — условный запрос (ETag/Last-Modified). Капча/403 — статус
  «закрыт доступ», не обходим. Сайт упал — берём последнюю сохранённую копию и помечаем «не обновилось».
- **Адаптеры УК** (`pif/sources/<ук>.py`): по одному на управляющую компанию, подхватываются автоматически.
  Разбор — отдельные чистые функции, на незнакомых данных бросают `UnknownFormat` (никаких тихих нулей).
  Тесты — на настоящих ответах сайтов в `tests/fixtures/<ук>/`.
- **Нормализация** (`pif/normalize.py`): слияние выгрузок по дате (свежая побеждает), выбросы, дробление паёв
  (цена прыгнула в 10/100/1000 раз, а СЧА — нет), СЧА в тысячах вместо рублей. Каждое исправление — в журнал.
  Пропуски не заполняются.
- **Притоки** (`pif/flows.py`): `приток = СЧА_м − СЧА_{м−1} × пай_м / пай_{м−1}` по последней точке месяца.
  Логика: если бы паёв не выдавали и не гасили, СЧА изменилась бы ровно как пай. Всё сверх — деньги пайщиков.
  Нет точки за прошлый месяц — приток не считается (пропуск, не ноль). Валютные фонды — в рубли по курсу ЦБ.
  Тест с заранее известными числами: `tests/test_flows.py`.
- **Сверка доходности** (`pif/returns.py`): доходность пая за 1/3/6/12 мес по нашему ряду vs официальная
  с сайта УК на ту же дату; > 0,5 п. п. — в отчёт и значок ≠ на сайте.
- **Публикация**: `--strict` возвращает ошибку, если в отчёте есть ошибки сбора/разбора; тогда CI не коммитит
  данные и Vercel не деплоит. Расхождения доходности публикацию не блокируют.
- **Сайт** (`site/`, Astro): статическая сборка, base path `/pif/` (меняется переменной `PIF_BASE`), страницы
  `/pif/fund/<номер правил>/`, `/pif/uk/<ИНН>/` готовым HTML, фильтры и сортировка в адресной строке,
  графики — uPlot (MIT), шрифты локально (@fontsource, OFL). Ничего внешнего не грузится.

## Решения, которые стоит уметь объяснить

- **Почему 395, а не 559 фондов.** В заголовке задания «розничные». 164 действующих фонда — только для
  квалифицированных инвесторов, их отбросили и написали об этом на сайте.
- **Почему не все УК собраны.** Часть сайтов недоступна из сети, где работает сборщик (ВИМ, Атон, БКС, РСХБ,
  ААА, Ак Барс и др. — 403 или таймаут из-за рубежа). Это показано статусом с причиной. С российского IP
  они, скорее всего, откроются — это первое, что делать дальше.
- **Почему данные лежат в git.** Сайт — чистая статика, Vercel собирает его из `data/site` и `data/series`.
  Сырые файлы (xlsx/json/html с сайтов) в git не лежат — только манифест с SHA-256.
- **Почему CI по расписанию может не видеть часть УК.** GitHub Actions работают с зарубежных IP. Честное
  решение — self-hosted runner на российском сервере; пока описано как ограничение.

## Известные проблемы и что нашли сами

- Фонды с выплатой дохода: доходность считается с учётом выплат по формуле УК. Где суммы выплат УК публикует
  только в PDF-сообщениях (ТКБ, часть фондов Альфы, Т-Капитал TPAY), остаётся расхождение — оно показано, а
  не спрятано (24 из 717 сверок).
- ТРИНФИКО отвечает 403 именно на наш User-Agent со ссылкой на репозиторий. Подменять UA ради доступа не стали —
  это было бы обходом блокировки.
- Найденные ошибки на сайтах УК (полезно рассказать): у Альфы подпись «на 30.10» над цифрами на 30.09;
  у Метрополя за 05.03.2026 СЧА и цена переставлены; у Арикапитала неверный номер правил в карточке;
  в реестре ЦБ фонд 4471-СД «Первой» записан открытым, а УК называет его интервальным.
- Ссылка «Сравнить УК» ведёт на https://algosphere.tech/sravnenie/?inn=… — сам раздел пока не умеет
  открываться на конкретной УК (это SPA без параметров). Описать в README как точку интеграции.

## Если на созвоне попросят правку — где что менять

- Новый фильтр или колонка в рейтинге: `site/src/pages/index.astro` (таблица и скрипт фильтров внизу файла).
- Порог расхождения доходности: `TOLERANCE_PP` в `pif/returns.py`.
- Формула притоков: `monthly_rows` в `pif/flows.py`, тест в `tests/test_flows.py`.
- Новая УК: скопировать любой небольшой адаптер (например, `pif/sources/verba.py`), поменять `uk_inns`.
- Базовый путь сайта: переменная `PIF_BASE` (по умолчанию `/pif/`).
- Пересобрать после правки: `python -m pif build && cd site && npm run build`.
