# Реестр розничных ПИФов

Все действующие открытые, интервальные и биржевые паевые фонды России для неквалифицированных инвесторов:
сколько в них денег (СЧА), сколько стоит пай и куда идут притоки. Данные — только из первичных источников,
у каждой точки ряда есть ссылка на источник.

**Демо:** https://pif-registry.vercel.app/pif/ (раздел живёт в подпапке `/pif/`, корень домена перенаправляет туда).

## Запуск одной командой

```bash
make install   # python-зависимости (pip install -e '.[dev]') и npm ci для сайта
make all       # реестр → сбор → нормализация → притоки → сверка → отчёт качества → сайт в site/dist/pif/
```

То же без make:

```bash
python -m pif all --strict     # данные; код 1, если отчёт качества запрещает публикацию
cd site && npm run build       # статический сайт
```

Отдельные шаги: `python -m pif registry | collect | build`, флаги `--offline` (только сохранённые копии,
без сети), `--only <ключ УК>` (собрать одну УК). Лог пишется в консоль и в `logs/run-*.log`.

Требования: Python 3.11+, Node.js 20.3+.

## Как устроено

```
pif/
  registry.py     реестр фондов: ЦБ (фонды, УК) + Мосбиржа (ISIN, тикер)
  http.py         вежливый клиент: 1 запрос/с на домен, User-Agent, кэш raw/, манифест, условные запросы
  sources/        по адаптеру на управляющую компанию (подхватываются автоматически)
  normalize.py    одна непрерывная история фонда, журнал исправлений
  flows.py        месячные точки и чистые притоки, своды
  returns.py      доходность пая и сверка с официальной
  fx.py           курсы ЦБ для валютных фондов
  build.py        сборка данных для сайта и отчёт качества
site/             Astro, статическая сборка с base path /pif/
data/             результат (в git): манифест, реестр, собранные ряды, отчёт качества, данные сайта
raw/              сырые ответы источников (не в git, восстанавливаются сбором по манифесту)
tests/            тесты разборщиков на настоящих фикстурах, нормализации, притоков, HTTP-клиента
```

### Реестр фондов

- **Список фондов** — [реестр ПИФ Банка России](https://www.cbr.ru/registries/RSCI/) (xlsx «Сведения о паевых
  инвестиционных фондах»). Отбор: тип «Открытый», «Интервальный» или «Биржевой»; статус «Сформирован» или
  «Формируется»; паи не только для квалифицированных инвесторов. На дату сбора — 395 фондов у 52 УК
  (ещё 164 действующих фонда этих типов — только для квалов, в розничный реестр не входят).
- **ИНН и сайт УК** — реестр лицензий управляющих компаний Банка России, склейка по ОГРН (в реестре фондов ИНН нет).
- **ISIN и тикер** — справочник ценных бумаг Московской биржи (ISS, группа `stock_ppif`), склейка по номеру правил
  (поле «Номер государственной регистрации» совпадает с номером правил ДУ).
- Источник и дата реестра показаны на сайте (подвал и раздел «Источники и методика»).

### Сбор

- Только сайты самих управляющих компаний: API, которые дёргают графики на страницах фондов, выгрузки
  xlsx/csv, таблицы на страницах. Агрегаторы и сравнители не используются.
- Каждый ответ сохраняется в `raw/`, в `data/manifest.json` (и `.csv`) — адрес, фонды, формат, дата получения,
  SHA-256, статус.
- **Повторный запуск без изменений ничего не скачивает**: ответ моложе 20 часов берётся из кэша, старше —
  перепроверяется условным запросом (ETag / Last-Modified). Если источник отдаёт диапазон дат, запрашивается
  только хвост с последней собранной точки (с нахлёстом 10 дней), старые точки сохраняются.
- **Один сломанный сайт не роняет сбор**: каждая УК и каждый фонд обрабатываются отдельно, ошибка превращается
  в статус фонда с причиной. Если сайт не ответил, используется последняя сохранённая копия с пометкой
  «не обновилось».
- Не чаще одного запроса в секунду к сайту, честный User-Agent со ссылкой на репозиторий. Капчи, антибот-проверки
  и закрытые разделы не обходим — статус «сайт закрыл доступ». robots.txt соблюдается; исключения — в `pif/config.py`
  с причиной у каждого (см. «Что не получилось»).

### Разбор

Каждый формат разбирает отдельная чистая функция в адаптере УК. Структура проверяется явно; незнакомый формат —
исключение `UnknownFormat` с понятным текстом, а не пустой ряд или ноль. Ошибка разбора попадает в отчёт качества
и блокирует публикацию. На каждый разборщик есть тест на настоящем ответе сайта (`tests/fixtures/<ук>/`) и тест
на испорченной фикстуре.

### Нормализация

- Выгрузки сливаются по дате; если источники расходятся, берётся более свежая выгрузка — и это пишется в журнал.
- Значения в валюте пая и в рублях (официальный курс ЦБ на дату точки).
- Ложные скачки: **дробление/консолидация паёв** (цена изменилась в целое число раз при неизменной СЧА — прошлые
  цены приводятся к новому номиналу), **СЧА в тысячах вместо рублей** (скачок ровно в 1000 раз при спокойной цене),
  **одиночные выбросы** (точка уходит больше чем на 40% и сразу возвращается). Прочие большие движения не
  исправляются, а попадают в отчёт как аномалии.
- Недостающие точки не придумываются: пропуск на графике остаётся пропуском.
- Журнал исправлений — `data/corrections.csv`, на сайте — раздел «Качество данных» и карточка фонда.

### Притоки

Для каждого фонда и месяца берётся последняя опубликованная точка месяца, где есть и СЧА, и стоимость пая:

```
приток_м = СЧА_м − СЧА_{м−1} × (пай_м / пай_{м−1})
```

`СЧА_{м−1} × пай_м / пай_{м−1}` — сколько стоили бы прошлые паи сегодня, если бы их не выдавали и не гасили.
Всё, что сверх, — деньги пайщиков: плюс — выдача паёв, минус — погашение. Пример (`tests/test_flows.py`):
100 паёв по 10 ₽ → пай подорожал до 11 ₽ и выдали 20 паёв → СЧА 1 320 ₽, приток = 1 320 − 1 000 × 1,1 = 220 ₽.

- Нет точки за прошлый месяц — приток не считается (пропуск, а не ноль).
- Месяц формирования фонда — приток равен СЧА на конец месяца.
- Валютный фонд — приток в валюте пая, в рубли по курсу ЦБ на дату точки месяца.
- Выплата дохода пайщикам уменьшает и СЧА, и цену пая на одну и ту же величину на пай, поэтому в притоки не попадает.
- Квартал и год — суммы месяцев (последний полный месяц и 3 / 12 месяцев до него); если у фонда нет хоть одного
  месяца, сумма по нему не показывается.
- Своды по УК, типам, категориям и рынку — суммы по фондам. Каждый прогон проверяет, что сумма по фондам совпадает
  со всеми сводами (таблица «Сходимость» в отчёте качества).

### Самопроверка

- **Доходность** пая за 1, 3, 6 и 12 месяцев по собранному ряду сверяется с официальной, которую публикует сама УК
  (страница фонда / ключевой информационный документ), на ту же дату. Расхождение больше 0,5 п. п. — в отчёт
  качества с фондом, периодом и источником; на сайте — знак ≠ в рейтинге и пометка на карточке.
- Период считается «от конца месяца до конца месяца», если дата расчёта — последний рабочий день месяца
  (так считают УК: за 3 месяца на 30.10.2026 — от 31.07.2026), иначе — от того же числа N месяцев назад.
- Для фондов с выплатой дохода: `(пай_конец + Σ выплат на пай за период) / пай_начало − 1`, выплаты без
  реинвестирования. Этой формулой официальные цифры УК воспроизводятся до 0,01 п. п.; вариант с реинвестированием
  систематически завышал доходность.
- **Отчёт качества** строится после каждого прогона: `data/quality_report.md` и страница «Качество данных».
- **Ручная сверка** 15 случайных значений (фиксированный seed) — `data/manual_check.csv`.

### Публикация и CI

- `.github/workflows/ci.yml` — на каждый push: тесты, сборка данных из сохранённого сбора (и проверка, что она
  воспроизводится байт в байт), сборка сайта.
- `.github/workflows/update.yml` — по расписанию: восстановить кэш сырых ответов, `python -m pif all --strict`,
  и только если в отчёте качества нет ошибок сбора и разбора — закоммитить данные. Vercel собирает сайт из
  `main` автоматически. Расхождения с официальной доходностью публикацию не блокируют.

### Сайт

Astro, только статика: HTML, CSS, JS, JSON — без сервера и базы во время работы, без CDN, внешних шрифтов и
счётчиков. Базовый путь — `/pif/` (переменная `PIF_BASE`). Страницы фондов `/pif/fund/<номер правил>/` и УК
`/pif/uk/<ИНН>/` собираются готовым HTML. Фильтры и сортировка рейтинга хранятся в адресной строке. Выгрузки:
`/pif/data/rating.csv`, `/pif/data/fund/<номер правил>.csv` (с источником каждой точки).

## Что не получилось и почему

<!-- LIMITS:BEGIN -->
- **132 фонда без ряда.** Сайты 18 УК из сети, где работал сборщик (зарубежный сервер), не открываются: таймаут или
  403. Крупнейшие — ВИМ (39 фондов), Атон (19), БКС (16, антибот ServicePipe), РСХБ (14), ААА (13). Это видно
  статусом с причиной у каждого фонда. С российского IP большая часть, вероятно, откроется, но адаптеры к ним
  не написаны: без доступа нечего разбирать и не на чем проверить. ТРИНФИКО отвечает 403 именно на наш
  User-Agent со ссылкой на репозиторий — подменять его ради доступа не стали.
- **Доходность из PDF.** У части УК официальная доходность есть только в ключевом информационном документе (PDF).
  Где PDF читается текстом и не закрыт robots.txt, он разбирается (pypdf); у «Т-Капитала», «Сбербанк СЖ» и
  нескольких фондов «Альфа-Капитала» и «Первой» доходность не взята — фонд помечен предупреждением.
- **Выплаты дохода в PDF.** У нескольких фондов с выплатами (ТКБ, «Альфа-Капитал», «Т-Капитал») суммы выплат на пай
  опубликованы только в PDF-сообщениях, поэтому их доходность по ряду расходится с официальной — это 24 расхождения
  в отчёте качества, они не спрятаны.
- **robots.txt.** Соблюдается для всех сайтов (свой разборщик с поддержкой `*` и `$`). Исключения перечислены в
  `pif/config.py` поимённо с причиной: документированные публичные API (ISS Мосбиржи, API «Арсагеры») и пять сайтов
  УК, у которых robots.txt закрывает от поисковиков единственный источник обязательного раскрытия СЧА и пая
  (ПСБ, Ингосстрах-Инвестиции, Райффайзен, Капитал Лайф, ОЗОН). Убрать исключение — одна строка; фонды получат
  статус «закрыто robots.txt».
- **GitHub Actions работают с зарубежных IP**, поэтому расписание в CI видит те же сайты, что и сборщик. Надёжное
  решение — self-hosted runner на российском сервере.
- **Ссылка «Сравнить УК»** ведёт на https://algosphere.tech/sravnenie/ с параметром `?inn=`; сам раздел пока не умеет
  открываться на конкретной УК.
- **Ошибки и особенности источников, найденные при сборе:** у «Альфа-Капитала» подпись «Динамика на 30.10» стоит
  над цифрами на 30.09; у ТКБ адреса страниц не соответствуют фондам; у «Метрополя» за 05.03.2026 СЧА и цена
  переставлены местами (строка пропущена с предупреждением); у «Арикапитала» в карточке фонда неверный номер правил;
  в реестре ЦБ фонд 4471-СД «Первой» записан открытым, а УК называет его интервальным.
